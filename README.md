# ARD News Tracker

A modern PHP application built with the **Symfony** framework, containerized with **Docker**, and served by **Nginx**.

## Prerequisites

Ensure you have the following installed:
- [Docker](https://docker.com)
- [Docker Compose](https://docker.com)

## Tech Stack

- **PHP 8.2+** (FPM)
- **Symfony 7.x**
- **Doctrine ORM** (Database mapping and migrations)
- **Symfony AssetMapper** (Modern, build-less asset management)
- **Symfony UX Turbo** (Single-Page-App speed via Hotwire Turbo)
- **Symfony UX Chartjs** (Interactive data visualization)
- **Nginx** (Web Server)
- **MySQL** (Database)
- **Composer** (Dependency Manager)

## Getting Started

### 1. Clone the repository
```bash
git clone https://github.com/hannimoon/ard-news-tracker.git
cd ard-news-tracker
```

### 2. Environment & Docker Setup
Copy the distribution templates to create your local configuration:
```bash
# Symfony environment variables
cp .env .env.local

# Local Docker overrides (Xdebug, Mailpit, Ports)
cp docker-compose.override.yml.dist docker-compose.override.yml
```

### 2.1. Generate `APP_API_KEY`
Generate a secure API key and set it in `.env.local`:
```bash
# Generate a 64-character hex key
openssl rand -hex 32
```
Update `.env.local` with the generated value:
```dotenv
APP_API_KEY=your-generated-key-here
```

### 3. Build and Start Containers
```bash
docker compose up -d --build
```

### 4. Install Dependencies
```bash
docker compose exec symfony_php composer install
```

### 5. Database Migrations
```bash
docker compose exec symfony_php php bin/console doctrine:migrations:migrate --no-interaction
```

### 6. Install Frontend Assets (AssetMapper)
Download and cache third-party JavaScript dependencies (like jQuery, Turbo, and Chart.js) defined in `config/importmap.php`:
```bash
docker compose exec symfony_php php bin/console importmap:install
```

### 7. Initialize Symfony UX & Stimulus Assets
Publish the internal bundle assets (including Symfony UX Chartjs core controllers) into the public directory:
```bash
docker compose exec symfony_php php bin/console assets:install
```

## Database Management (Doctrine & Migrations)

The application uses **Doctrine ORM** to manage the MySQL database schema and entities (like `News` and `CronConfig`). Database updates are handled via migration files.

### Core Database Commands

Whenever you pull changes or modify an Entity class, use the following commands inside the PHP container:

#### 1. Generate a New Migration
Compares your PHP Entity mapping against the current database schema and generates a diff file in `migrations/`:
```bash
docker compose exec symfony_php php bin/console doctrine:migrations:diff
```

#### 2. Execute Pending Migrations
Applies all unexecuted migration files to your database schema safely:
```bash
docker compose exec symfony_php php bin/console doctrine:migrations:migrate --no-interaction
```

#### 3. Roll Back / Revert the Last Migration
If you need to undo the last schema change, you can safely revert the database layout by migrating back to the previous version version stamp or using the `prev` keyword:
```bash
# Revert exactly one step backward
docker compose exec symfony_php php bin/console doctrine:migrations:migrate prev

# Alternative: Revert to a specific version stamp
docker compose exec symfony_php php bin/console doctrine:migrations:migrate "DoctrineMigrations\Version20261031120000"
```
*⚠️ Note: Rolling back structural database migrations will drop the corresponding tables/columns and erase the data stored within them.*


## Asset Management, Turbo & Charts

The application utilizes **Symfony AssetMapper** to load JavaScript and CSS files natively in the browser as ECMAScript modules—completely eliminating the need for Node.js, Webpack, or npm installations. **jQuery**, **Symfony UX Turbo**, and **Symfony UX Chartjs** are integrated out of the box for the Admin Dashboard.

### Core Commands for Asset Setup

If you need to initialize or sync the frontend assets and bundles in a fresh environment, run the following commands:

#### 1. Download/Synchronize Importmap Packages
This command reads `importmap.php` and downloads all defined third-party JavaScript libraries (such as jQuery, Turbo, and Chart.js) locally into your project assets:
```bash
docker compose exec symfony_php php bin/console importmap:install
```

#### 2. Manual Package Management & Bundle Initialization (Reference)
If you ever need to manually install dependencies or publish internal asset vendor files:
```bash
# Require Symfony UX Turbo asset definitions
docker compose exec symfony_php php bin/console importmap:require @hotwired/turbo

# Publish internal Symfony UX Chartjs core assets to public/
docker compose exec symfony_php php bin/console assets:install
```

### ⚠️ Important Development Note on Symfony Turbo

Because **Symfony UX Turbo** is enabled, form submissions and link clicks are intercepted automatically via AJAX to deliver single-page-app speed. This means that jQuery's classic `$(document).ready()` event **will not fire again** during internal navigation or after submitting forms!

When writing custom JavaScript or jQuery logic that needs to run after a page transition or form refresh, you must bind your initializations to the `turbo:load` event instead:

```javascript
// assets/js/admin.js

function initMyScript() {
    // Your custom logic goes here (e.g., cron automation toggles)
}

// Supports both classic first-page load and dynamic Turbo updates
\((document).ready(initMyScript);\)(document).on('turbo:load', initMyScript);
```

If a specific form or link needs to be completely bypassed by Turbo (forcing a traditional hard browser reload), append the `data-turbo="false"` HTML attribute:
```html
<form action="..." method="POST" data-turbo="false">
```


## Running Tests

The application uses **PHPUnit** for automated testing.


### 1. Execute the Test Suite
To run all automated tests, execute the PHPUnit binary inside the PHP container:
```bash
docker compose exec symfony_php vendor/bin/phpunit
```

### 2. Generate Code Coverage Report (Optional)
If Xdebug is enabled and configured in `coverage` mode within your Dockerfile, you can generate a visual HTML coverage report:
```bash
docker compose exec symfony_php vendor/bin/phpunit --coverage-html public/coverage
```
*Once generated, you can view the interactive report by browsing to `http://localhost:8080/coverage/index.html`.*

## Development Features

### Xdebug
Xdebug is integrated into the PHP container but must be activated during the build process.
- **Enable/Disable:** Set `INSTALL_XDEBUG=true` or `false` in your `docker-compose.override.yml`.
- **Configuration:** To change the Xdebug mode (e.g., from `debug` to `coverage`), you must edit the `xdebug.mode` line directly in the **Dockerfile**.
- **Apply Changes:** Any changes to Xdebug settings require a rebuild:
  ```bash
  docker compose up -d --build
  ```

## News API Usage
The application exposes a protected news API endpoint at `/api/news`.

### Available query parameters
- `region` — filter by region
- `date` — filter by date (`YYYY-MM-DD`)
- `sentiment` — filter by sentiment (`good`, `bad`, `neutral`)
- `type` — filter by type (`story`, `webview`)
- `page` — pagination page number (default: `1`)
- `limit` — number of items per page (default: `10`)

### Authentication
The endpoint supports:
- `Authorization: Bearer <JWT token>`
- `X-API-KEY: <api-key>`

### Example request
```bash
curl "http://localhost:8080/api/news?region=DE&date=2026-05-12&type=story&page=1&limit=10" \
  -H "Authorization: Bearer <JWT_TOKEN>"
```

### API documentation
Browse the generated OpenAPI docs at:
- `http://localhost:8080/api/doc`

## CronConfig / Scheduled Import
The application stores a single cron configuration in the database using the `CronConfig` entity. This configuration controls automatic news imports and includes:
- `scheduleTime` — the UTC time when the import should run each day (format `HH:MM`, default `03:00`)
- `isActive` — whether the scheduled import is enabled

The scheduler uses this config to generate a daily cron job for `NewsImportMessage` if cron import is active. The admin dashboard exposes controls to update the schedule time and enable or disable the automatic import.

## Optional: Initial Data Import
To populate your database with the latest news immediately after setup, run the import command:
```bash
docker compose exec symfony_php php bin/console app:import-news
```
